# 内部構成

[README](../README.md) · [利用ガイド](usage.md) · [ローカルでの動作確認](local-development.md)

## 責務

単一Botプロセス内のモジュールで構成し、VOICEVOX・yt-dlp・FFmpegを利用します。

| モジュール | 役割 |
| --- | --- |
| `src/index.ts` | Discordイベント・コマンド、サーバーごとのSession管理 |
| `src/queue.ts` / `src/tts.ts` | 読み上げキュー、VOICEVOX呼び出しと起動管理 |
| `src/text.ts` | テキスト整形と辞書適用 |
| `src/media/` | 動画キュー、YouTube取得アダプター、リスト表示 |
| `src/audio/mixer.ts` | PCMミックス、動画ゲイン、フェード |
| `src/audio/process.ts` | 外部プロセスとデコード |
| `src/audio.ts` | 合成済み音声のDiscord送信 |

SessionはVC接続・読み上げキュー・動画キュー・ミキサーを所有します。サーバー間でこれらの状態を共有しません。VOICEVOXの起動管理は共通で、利用中サーバーの有無を管理します。

## 音声処理

PCMは48kHz・ステレオ・signed 16bit LE、1フレーム20msです。読み上げと動画を加算し、16bit範囲を超える信号をクリップします。音源による歪みは残る可能性があり、高度なリミッターはありません。

動画全体はメモリに保持せず、子プロセスのパイプと有限バッファでストリーム処理します。FFmpegの標準出力は中継バッファで受け、プロセス終了後も末尾まで読み切ります。送信側の先読み上限は5フレーム（100ms）です。一時停止中は動画PCMの読み取りを止め、バックプレッシャーで取得・デコードを抑制します。

開始通知とキュー完了はAudioResourceの再生位置から1パケット遅れた位置で判断します。取得や合成の完了だけでは次へ進みません。これはBot送信側の位置であり、受信端末での再生完了を保証するものではありません。

読み上げ対象URLはHTTP(S)・標準ポートに限定し、公開IP判定、解決IPへの接続固定、実接続先照合、リダイレクトごとの再検証を行います。取得上限は3秒・1MBです。

## タイムアウトと終了処理

| 処理 | 上限 |
| --- | --- |
| 読み上げ音声再生 | 60秒 |
| 動画メタデータ取得 | 30秒 |
| 動画タイトル取得 | 8秒 |
| PCM入力停止 | 30秒（一時停止中の動画は除外） |
| 動画1ジョブ | 125分（一時停止時間を含む） |
| VC再接続待ち | 接続開始5秒、Ready20秒 |

読み上げや動画単体の失敗は後続へ進めます。動画の出力が完了した場合は残った取得プロセスを中断し、後片付けの例外はログへ記録します。

退出時はキュー・音声取得・デコードを中断し、ストリーム・タイマー・VC接続を解放します。POSIX環境では外部プロセスをグループ単位で終了し、2秒で終了しなければ強制終了します。Windowsでの子孫プロセス終了は未検証です。

共有出力の致命的障害や再接続失敗時は、そのサーバーのSessionを終了します。自動再参加・キュー復元はなく、再利用には `/join` が必要です。準備中の退出は待機を中断し、他サーバーが利用中のVOICEVOXは維持します。
